# 챌린지 상태 프로세스 개편 + 성능 개선 플랜

작성 2026-08-25 · 상태: 스펙 확정(착수 대기)

## 1. 배경 — 상태값이 3곳에서 갈라져 있다

| 정의 위치 | 허용값 |
|---|---|
| `docs/spec.md:28`, `src/gas/Setup.gs:20`, `public/js/lib/setup.js:3` | 모집중/선발중/진행중/종료 |
| `src/gas/AdminHub.gs:100` (실제 저장 경로) | 종료/모집중/진행중 — 선발중 저장 불가 |
| 프론트 | `'모집중'` 하드코딩 (admin.js:227·357·529, landing.js:199) |

파생 피해
- 신규 캠페인 100% `모집중` — 프론트(`admin.js:529`) + GAS(`Setup.gs:119`) **이중 하드코딩**
- **일일 자동화 전면 정지** — `Automation.gs:240`은 `진행중`만 처리, `진행중`을 쓰는 코드는 "재개" 버튼뿐
- 모집기간이 장식 — `모집시작`/`모집마감`을 오늘과 비교하는 코드 0줄
- `선발중`은 쓰는 코드 없음 → 실데이터 0건 예상

## 2. 확정 스펙

### 2-1. 상태 4종 및 전이

| From | To | 트리거 |
|---|---|---|
| 준비 | 모집중 | 수동 — "모집 시작하기" 버튼 |
| 모집중 | 운영중 | 시간 — 오늘 > 모집마감 (파생) |
| 운영중 | 완료 | 시간 — 오늘 > 마지막 회차 마감일 (파생) |
| any | any | 수동 override (확인창 경유) |

- **운영종료일 = WeekMissions의 마지막 회차 마감일** (스키마 변경 0)
- **역방향 전이 허용** — 모집중→준비 강등, 완료→운영중 재개. stagebox에 secondary 버튼 1개

### 2-2. 시간 전이는 파생 계산 (시트 저장 안 함)

시트에는 수동 상태만(`준비`/`모집중`/`완료`) 저장. `운영중`은 저장하지 않고 조회 시 날짜로 계산.

근거: 이 프로젝트의 `dailyTrigger`가 이미 조용히 멈춰 있다(§1). 상태 전이를 트리거에 얹으면 같은 방식으로 또 멈춘다. 부수 효과로 기존 시트 데이터 무손상.

### 2-3. 탭 접근 — 잠금 아님, 안내 배너

**모든 탭은 준비 단계에서도 열려 있고 미리 설정 가능하다.** 관리/운영/리워드 탭 상단에 안내 배너만 표시:

> 아직 준비가 완료되지 않았습니다. 미리 설정해 두실 수 있지만 참가자에게는 공개되지 않습니다. → 준비 탭으로 이동

- 라우트 가드·lock 아이콘·클릭 차단·비활성 처리 **전부 불필요**
- 배너 내 이동 링크는 ④ 어휘(텍스트+화살표, 테두리 금지)
- 착수 시 기존 안내/공지 컴포넌트가 있는지 먼저 확인하고 있으면 재사용

### 2-4. 배지 시각 체계 — 시맨틱 컬러

형태는 4상태 동일(`.badge` 기본형, radius-sm, soft 배경 + 헤어라인). **채움 금지** — 채움은 CTA 어휘다.

| 상태 | 배경 / 텍스트 |
|---|---|
| 준비 | `--color-surface-2` / `--color-ink-muted` |
| 모집중 | `--color-primary-soft` / `--color-primary-hover` |
| 운영중 | `--color-warning-soft`(신규) / `--color-warning-on`(신규) |
| 완료 | `--color-success-soft` / `--color-success-on`(신규) |

MASTER §1이 warning='운영·마감임박', success='선발·완료'로 용도를 이미 명시 → 새 규칙 발명 불필요.
완화책: 홈 카드 '수정' 블루 텍스트(admin.js:358)를 ink-muted로 내려 CTA 경합 제거.

### 2-5. 기타 확정

- 버튼 라벨 **"모집 시작하기"** (버튼은 상태가 아니라 결과를 말한다) + confirmModal `danger:false`
- 버튼 위치: appbar 아님 → **준비 탭 본문 하단 stagebox**. appbar 우측은 전역 유틸 영역이라 계층이 다르고, 거기 두면 4탭 어디서나 눌려 맥락 소실
- `.endbox`(hub.css:184, admin.js:909)를 `.stagebox`로 일반화 → 종료/재개 버튼도 흡수, 컴포넌트 수 -1
- **스텝 인디케이터 불필요** — 탭 4개가 이미 진행 순서와 1:1 대응, appbar 3번째 줄 방지
- 탭 개명 '마케팅'→'준비' (`SECTIONS` admin.js:102 한 곳). 라우트 키 `mkt`·CSS 클래스는 URL 호환 위해 유지. 확성기 아이콘도 교체

### 2-6. 마이그레이션 — 시트 일괄 UPDATE 불필요

| 기존값 | 새 값 |
|---|---|
| `''`(빈값) | 준비 |
| 모집중 | 모집중 (모집마감 경과 시 파생 운영중) |
| 선발중 / 진행중 | 모집중 |
| 종료 | 완료 |

`normalizeStatus()`를 읽기 경로 전부(`campaigns_`·`campaignDetail_`·`boardData_`·`isRecruiting_`)에 통과시키면 기존 행 무손상. 선택적으로 1회성 `migrateStatus()`로 시트값도 정리.

## 3. 성능 — 병목은 왕복 횟수

70KB `admin.js`는 gzip 후 ~25KB. **코드 스플리팅 권장 안 함.**

| 병목 | 실측 |
|---|---|
| 홈→4탭 순회 | 6 GET = 12 HTTP RTT (GAS 302 리다이렉트로 왕복 2회) |
| 주차 저장 1번 | saveMission+openWeek+weekSubmissions = 3왕복 |
| 우수 별표 1번 | `bumpRev_`가 캠페인 캐시 통째 소각 → 직후 조회 100% 미스 |
| 알림톡 발송 | 참가자 수만큼 순차 UrlFetch + 건당 append → 100명 시 6분 한도 위험 |
| `Automation.gs:206` | 루프 안 시트 풀리드 — 진성 N+1 |
| `admin.html:16` | html2canvas 197KB 항상 로드 (준비 탭에서만 필요) |
| `admin.js:307` | 삭제된 voc-daemon을 홈 렌더마다 호출 — 죽은 코드 |

디자인 측 체감 원인: 별표 하나에 전체 innerHTML 재생성 + 재요청, 스켈레톤 0건, 비동기 버튼 피드백 3종 혼재(반려·우수·선발은 무피드백 → 중복 클릭).
